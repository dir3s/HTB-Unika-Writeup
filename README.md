# Звіт про тестування на проникнення: Unika (Hack The Box)

## 1. Executive Summary
Під час тестування безпеки Windows-машини Unika було виявлено критичну вразливість локального включення файлів (LFI) у веб-додатку. Через архітектурні особливості ОС Windows ця вразливість дозволила здійснити атаку UNC Path Injection. У результаті веб-сервер примусово звернувся до підконтрольного зловмиснику вузла, що призвело до витоку NTLMv2-хешу адміністратора. Після успішного офлайн-розшифрування пароля було отримано повний адміністративний доступ до системи через службу віддаленого керування WinRM.

## 2. Technical Walkthrough

### 2.1. Розвідка та сканування мережі (Reconnaissance)
Тестування розпочалося з базового сканування IP-адреси цільової машини. Було виявлено відкритий TCP-порт 80 (HTTP).

### 2.2. Vulnerability Discovery
Під час ручного аналізу веб-додатка було виявлено функціонал перемикання мови. Натискання на кнопку зміни мови генерувало URL-запит із параметром `?page=`. Передача назви файлу або сторінки через URL-параметр є класичною ознакою потенційної вразливості **LFI**.

Враховуючи, що цільова машина працює на базі Windows, вектор експлуатації LFI тут відрізняється від Linux. У Windows можна передати в параметр не просто локальний шлях, а мережевий (UNC-шлях), змусивши сервер звернутися до зовнішнього ресурсу.

### 2.3. Експлуатація: Примусова автентифікація (Forced Authentication)
Для реалізації атаки було використано утиліту **Responder**. 

> **Довідка:** Responder - це інструмент, який створює підроблені мережеві сервери (наприклад, файловий SMB-сервер). Коли Windows намагається завантажити файл із мережевого ресурсу, вона використовує механізм Single Sign-On (SSO) і автоматично надсилає зашифровані облікові дані (NTLM-хеш) поточного користувача для авторизації. Responder виступає в ролі такого підробленого сервера: він ловить цей хеш і зберігає його для подальшого розшифрування.

Responder було запущено в режимі прослуховування на інтерфейсі тунелю:

### 2.4. Злам пароля та отримання доступу (Credential & Initial Access)
Отриманий хеш було збережено у текстовий файл. Наступним кроком пароль необхідно було розшифрувати. Для офлайн-перебору (брутфорсу) було використано утиліту **Hashcat** разом із словником `rockyou.txt`. Розшифрування завершилося успішно, виявивши валідні облікові дані.

<img width="952" height="662" alt="image" src="https://github.com/user-attachments/assets/afe1dc19-06ae-4b54-b337-95c84f60ca7c" />

Маючи на руках пароль адміністратора, для входу в систему було обрано утиліту **Evil-WinRM**. 

> Windows Remote Management (WinRM) - це вбудований протокол віддаленого керування Windows (аналог SSH), який зазвичай працює на портах 5985/5986. Оскільки було отримано легітимні облікові дані, підключення через WinRM є найчистішим і найстабільнішим способом отримати повноцінну PowerShell від імені адміністратора без необхідності завантажувати додаткові експлойти чи бекдори.

Команда для підключення:
```bash
evil-winrm -i unika.htb -u Administrator -p 'badminton'
```

Підключення пройшло успішно. Через отриману PowerShell-сесію було знайдено та прочитано фінальний прапорець (Flag).

## 3. Attack Chain

1. **Reconnaissance:** Виявлення веб-сервера на порту 80 (Windows/Apache).
2. **Vulnerability Discovery:** Знаходження параметра `?page=` (LFI).
3. **Execution:** Впровадження UNC-шляху для ініціації вихідного SMB-з'єднання від сервера.
4. **Credential Access:** Перехоплення NetNTLMv2-хешу за допомогою Responder.
5. **Cracking:** Успішний офлайн-перебір пароля за допомогою Hashcat та словника rockyou.
6. **System Compromise:** Авторизація через службу WinRM з отриманими правами та повний контроль над системою.

---

## 4. Remediation
Для усунення виявлених вразливостей рекомендується:
1. **Захист від LFI:** Впровадити строгу валідацію вхідних даних для параметра `?page`. Використовувати підхід whitelist, дозволяючи завантажувати лише заздалегідь визначені безпечні файли.
2. **Мережева ізоляція:** Налаштувати Firewall на блокування вихідного трафіку на порт 445 (SMB) та 139 (NetBIOS) до зовнішніх мереж.
3. **Політика паролів:** Заборонити використання слабких і словникових паролів, запровадивши політику складності та довжини паролів, щоб унеможливити швидкий офлайн-злам перехоплених хешів.
